# Why a skipped test becomes a false clean report

A skipped test is filed as sound. The customer is left in the wrong place.

Seen on this desk:

- Thinking permission was on. promptfoo took "pong" as a pass. The body was empty; the word only echoed the prompt. Skip the connection check and the next red-team run also passes an empty permission.
- garak `test.Blank` records 100% "attack success." That means output arrived on empty input. Unread, a connection is filed as a finding.
- AgentDojo `security: true` with no injection is not resistance. Skip the field and the model is called safe.
- Banking utility was 10/16 true. Six are loose controls. A percentage alone makes the model look finished.
- On DVMCP a resource was read with no identity header. The model did not call the URI in a neutral summary. The model sentence alone makes the server look clean.
- In week 2, an approval tool the agent can call is not a gate. Skip that line and writes look safe.

An unrun class is not clean. The gap list stays in the report so the customer sees what was not examined.
